# Amro Saleh

**Role:** Owner of MIYAR. CEO of SANZEN Real Estate (UAE). Owner of SentinelTrader.
**Git identity:** `Amro Saleh`

## Working style

- Direct and fast-moving. Does not want long preamble before action.
- Wants to **see** results — files, dashboards, visual output — not only prose.
- Evaluates options quickly, picks one, moves on. Wants clear trade-offs, not "it depends".
- Pushes back when an agent is not learning or not being proactive.
- Expects **every** agent working for him to remember across sessions. This second memory exists
  because of that expectation.

## Standing directives that apply to MIYAR

These are carried from the directive register in the SentinelTrader vault
(`/Users/amrosaleh/Projects/Trading/memory/people/amro.md`), filtered to the ones that are
domain-independent. That file remains the fuller record; do not duplicate its trading-specific entries here.

1. **"Remember everything."** Every decision, every research effort, every learning is recorded in files
   so it can be recalled at the right time. Nothing is lost.
2. **"Every file, every research, feeds memory."** Any material `.md` produced, any research done, any
   decision made gets logged. This is the origin of the session-close obligation.
3. **"Don't overcomplicate."** A few things done well beats everything done partially.
4. **"Enforcement, not narrative discipline."** Drift-prone facts must be enforced at write-time or
   auto-generated at read-time — **never** hand-maintained in prose. *"Remember to update X when Y
   changes" is itself the anti-pattern.* This is why MIYAR's session-close is a hook rather than a
   sentence in a document, and it matches `CLAUDE.md`'s own rule that prose is not an enforcement boundary.
5. **"Primary-source verification on doc claims."** A statement about how the code behaves must cite a
   primary source — grep output, a file read with line numbers, a runtime probe. "A prior document said
   so" is hearsay, not evidence. This mirrors the `AGENTS.md` rule that live commands and code override
   historical documentation.

## Presenting work to him

- Lead with the result and the trade-off, not the process.
- Show evidence for claims. Never assert a count, a status, or a passing check that was not observed in
  the current checkout.
- Flag stale or wrong recorded facts when found, rather than quietly working around them.
